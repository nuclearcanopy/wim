# audit, november 2026

Whole-repo audit at `77839e4`: security, reliability, performance, ui, ux,
packaging, tests. Findings that were cheap and safe to fix are fixed on
branch `audit/2026-11`; the rest are listed below with severity so none
is silently dropped. This sits beside `performance-audit-roadmap.md`, which
stays the checklist for the larger measured performance work.

## method

- baseline: `cargo fmt --check`, `clippy --all-targets -D warnings`,
  `cargo test --locked` all clean at `77839e4` (1609 tests).
- three read-only source reviews (security, reliability, ui/ux), each
  finding checked against the code before acting on it.
- `cargo audit`, `cargo machete`.
- pty harness (python `pty` + `pyte`) for terminal sizes, SIGTERM,
  idle redraw cost and startup; release builds of base and branch.
- live run against a real Navidrome server and a TorBox account, with
  credentials read only from files and every output scrubbed. Read-only
  commands and playback only; nothing was starred, added or deleted.

## third pass: the last open items

| id | what | change |
|---|---|---|
| M8 | a `playlist-pos` event in flight across a queue rewrite resolved to the wrong track | the queue keeps mpv's entry id for every entry (`loadfile` replies carry it, `start-file` names it); "what is playing" resolves by id, so a stale event names nothing and is dropped. `playlist-pos` only speaks for entries without an id. Verified against mpv 0.41 (`loadfile_ids_match_start_file_events_and_the_playlist_property`) and live against Navidrome (skip and advance pick the right track) |
| M4 | queue/mpv reconcile after a timeout compared lengths | now compares ids: removes the entries mpv took on its own from mpv *by position*, forgets the recorded ones it never took, and never touches the playing entry |
| P4 | two wims overwrote each other's state | merge on save under a file lock (`fsutil::locked_update`): play history (per-track three-way merge: deltas add, days union, newest play wins, this side's cache changes win), favorites (this side's stars and unstars applied to what is on disk), command history and ranks. Session state (queue, resume position), settings and derived caches stay last writer wins; the config keeps the other writer's copy as `config.toml.other.bak` (0600) |
| P7 | no format versions | `version` in state, favorites, saved queues, the library index and the enrichment cache; a header row in `index.ndjson`. A file from a newer wim is read as far as it parses and copied aside (`.vN.bak`) before this wim writes over it; an unreadable one is kept as `.corrupt` |
| F20 | subtitle sidecar written through a planted symlink | `fsutil::atomic_write_beside` replaces the link instead; the remaining in-place state writes (ranks, history, suggest enrichment, shellsong state) are atomic too |
| nav pings | the profile manager waited on every server to open | opens at once, statuses fill in per server (matched by url and user) |
| `paste` | unmaintained advisory | lofty 0.25 (still depends on it), advisory ignored in `.cargo/audit.toml` with the reason, `cargo audit --deny warnings` in CI |
| B6/B7 | per-frame cost | profiled with callgrind on a 300x80 terminal with 64 bands: 82% of wim's instructions were ratatui's whole-screen diff, our drawing 6%. So allocations in the draw closure are not the cost; frames are. A paused player stopped playing but kept redrawing at the display rate (0.25s cpu per 8s at 300x80); it now idles (0.04s). Ordinary animation is capped at 30fps (playing 0.24s -> 0.07s); scrubbing and move mode keep the display rate |

## measured, not changed

- startup: first screen about 3ms for both front-ends.
- the remaining paused cost is the 10Hz idle redraw (0.5% cpu at 300x80).

## still open

- `paste` (RUSTSEC-2024-0436) is unmaintained and a build-time dependency of
  `lofty`; ignored on purpose.
- merge on save is not applied to the config (a merge cannot know which of
  two edits to one setting is meant), the saved queue and the resume
  position (one session's state); those keep last-writer-wins, and the second
  wim says so when it starts.
- bindings.toml and vars.toml (shellsong state) have no format number.
- the in-memory index does not absorb the other wim's plays until restart
  (the file does; the next save merges again).
